# JRiver Remote 2.6.0

## Highlights

- **Adaptive Chrome.** A new dynamic UI system that automatically hides the top header and bottom mini-player when you scroll down, providing an immersive, content-first experience. The chrome reappears instantly when you scroll up or reach the top of the list.
- **Performance Refactoring.** Major screens (Library, Artists, Favorites, Queue) have been refactored to use high-performance sliver layouts, ensuring smooth scrolling even with large music collections.

## Improvements

### User Interface

- **Intelligent Visibility**: Integrated `ScrollChromeListener` across all primary navigation tabs. This coordinates the hiding/showing of the main application header and the mini-player based on user scrolling context.
- **Expanded Viewport**: By hiding non-essential UI elements during active browsing, the available content area is significantly increased, making it easier to browse long lists of artists, albums, or tracks.
- **Animated Transitions**: Smooth, physics-based animations handle the entry and exit of UI components for a polished, modern feel.

### Core & Library

- **Sliver Migration**: Replaced standard `ListView` components with `CustomScrollView` and `SliverList` architectures in:
    - Artists and Random library tabs.
    - Favorites list.
    - Browsing content views.
    - Playback Queue screen.
    - Downloaded Artists (Offline) screen.
- **State Persistence**: Ensuring the UI chrome state is correctly reset when switching between tabs or navigating through the library hierarchy.

## Migration notes for developers

- **Custom Scroll Views**: Many screens now use `CustomScrollView`. If adding new widgets to these screens, ensure they are wrapped in a `SliverToBoxAdapter` or implemented as a `Sliver` widget.
- **Chrome Visibility**: The `libraryChromeVisibleProvider` now controls the global visibility of the root header and mini-player. Use this provider if you need to manually toggle chrome visibility from a specific feature.
