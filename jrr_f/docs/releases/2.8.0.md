# JRiver Remote 2.8.0

## Highlights

- **Riverpod is now the only DI container.** The `get_it` package and `lib/core/di/injection.dart` are gone; every long-lived dependency — repositories, services, the database, the connection repo — is constructed through Riverpod providers and wired into the runtime container in `main.dart`.
- **Reactive `McwsClient`.** The session-scoped MCWS client lives in a `ValueListenable` on `ConnectionRepository`. `mcwsClientProvider` subscribes to that listenable and self-invalidates whenever the session changes, so repositories always see the current client.
- **One provider per widget.** Every routable screen and every reusable tile now consumes either a single dedicated view model or a single existing notifier that already exposes state + commands. The widget tree no longer reaches into multiple providers per build.

## Improvements

### Dependency injection (`get_it` → Riverpod)

- **Repositories take their dependencies via constructor.** `PlayerRepositoryImpl`, `ZoneRepositoryImpl`, `QueueRepositoryImpl`, `LibraryRepositoryImpl`, `LocalQueueRepositoryImpl`, and `FavoritesRepositoryImpl` no longer reach out to `getIt` from inside their methods; MCWS-backed repos receive a `McwsClient Function()` resolver lambda.
- **Audio services receive their deps via constructor.** `LocalPlayerService`, `AndroidAutoPlayerService`, and `AndroidAutoSessionService` all take their repositories, the talker, and the MCWS client resolver through named constructor parameters.
- **Session-scoped `McwsClient` exposed via `ValueListenable`.** `ConnectionRepository.clientListenable` replaces the old `getIt.pushNewScope` / `popScope` dance. Riverpod's `mcwsClientProvider` listens to the notifier and invalidates itself on every session change.
- **Bootstrap simplified.** `main.dart` constructs everything in a single linear sequence and hands the result to a `ProviderContainer` used by `UncontrolledProviderScope`. `DownloadService.start()` fires via an eager `container.read`.

### Widget view models (one provider per widget)

- **Per-screen view models with dedicated state classes.** New view models for `NowPlayingScreen`, `MiniPlayerPanel`, `QueueScreen`, `ZoneListScreen`, `ServerManagerScreen`, `ServerSetupScreen`, and `DownloadedArtistsScreen`. State and notifier live in separate files (`*_view_state.dart` / `*_view_model.dart`).
- **Sub-widgets demoted to `StatelessWidget`.** Inner `ConsumerWidget` consumers that each ran their own `playerProvider.select(...)` calls now receive their slice as constructor parameters from the screen — fewer subscriptions, simpler diffing.
- **Rebuild localization for high-churn slices.** `NowPlayingScreen` and `MiniPlayerPanel` use a record-shaped `.select` at the top of `build` that omits `positionMs`/`progress`; `_ProgressSection` / `_ProgressBar` stay as `ConsumerWidget`s and `.select` the high-churn fields from the same view model — so position ticks no longer rebuild the surrounding tree.
- **Family-keyed view models for reusable tiles.** `LibraryItemTileViewModel` (keyed by `fileKey`) and `AlbumRowTileViewModel` (keyed by `Album`) pre-compute popup-item visibility flags and host the play / playNext / add-to-queue / download / cancel / delete commands. `TracksPopupMenuViewModel` (keyed by `Tracks`) does the same for the shared popup-menu widget.
- **Logging out of widgets.** `talkerProvider` is no longer read from any widget; transient debug logs that lived in widget builds are gone.

### Layout fix

- **Mini-player hides on scroll in the wide layout.** `TwoPanelShell._MainPanel` now watches `libraryChromeVisibleProvider` and animates the mini-player out on scroll-down, matching the narrow layout's existing behaviour.

## Migration notes for developers

- **DI access.** Use `ref.read(xProvider)` / `ref.watch(xProvider)` everywhere. `getIt` has been removed; the package is no longer in `pubspec.yaml`.
- **MCWS client resolution.** From a widget or provider, use `ref.read(mcwsClientProvider)`. From a service constructed in `main.dart`, accept a `McwsClient Function()` resolver and call it lazily — the closure should read `connectionRepository.clientListenable.value` and throw if no session is bound.
- **View-model convention.** Each routable screen / reusable tile lives in three files: `<screen>.dart` (widget), `<screen>_view_state.dart` (freezed state), `<screen>_view_model.dart` (Riverpod notifier). The widget watches one provider, reads the notifier once, and forwards callbacks. Sub-widgets prefer constructor props; promote a sub-widget back to `ConsumerWidget` only when it consumes a high-churn slice that warrants local rebuild — and in that case it `.select`s from the screen's own view model, not from underlying providers.
- **Reusable tiles.** Per-item state belongs in an `autoDispose` family-keyed view model so memory stays bounded as users scroll long lists.
- **Tests.** Repository / view-model tests use `ProviderContainer(overrides: [...])`; the legacy `getIt.reset()` calls in `mcws_client_test.dart` and `connection_repository_test.dart` have been removed.
