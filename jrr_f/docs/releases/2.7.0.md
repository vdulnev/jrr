# JRiver Remote 2.7.0

## Highlights

- **Android Auto support.** JRiver Remote now works as a media source in your car. Browse downloaded music, view recently played tracks, and use voice search to play albums and artists — all from the head unit. Android Auto is modeled as a third virtual audio zone alongside Local and Offline, with automatic detection and switching when you connect to a vehicle.
- **Library scrolling polish.** Album and track lists now use sliver-based layouts for smoother scrolling, and multi-disc albums get a dedicated list widget that integrates cleanly into the new scroll architecture.
- **Faster, more precise MCWS queries.** The networking layer adopts a new `audioSearch` method that streamlines API calls and removes redundant `[Media Type]=Audio` filters across the client.

## Improvements

### Android Auto

- **Virtual zone**: Android Auto is exposed as a selectable zone, with a dedicated car icon and "ANDROID AUTO" badge in the zone picker. The audio-quality picker is available for AA streams.
- **Background playback**: Integrates `audio_service` with `just_audio` for system-level media controls, lock-screen playback, and reliable foreground-service transitions on Android.
- **Browse tree**: Full hierarchy in the car — Downloads, Recent, Artists, and Albums — backed by `RecentlyPlayedRepository` for playback history.
- **Voice search**: A dedicated `VoiceIntentResolver` interprets structured AA intents (e.g. "play album X by Y") using `focus`, `artist`, and `album` extras, with a fallback for raw queries.
- **Artwork**: Cached album art is exposed to the head unit via a `FileProvider` and content URI scheme, with prioritized URI handling in `MediaItemMapper`.
- **AAOS compatibility**: Adds `android.hardware.type.automotive` and `com.android.automotive` metadata so a single APK works on both phone-AA and native Automotive OS head units.
- **Session detection**: `AndroidAutoSessionService` debounces connect/disconnect events; the zone list updates live via `androidAutoConnectedProvider`.

### Library & UI

- **Sliver migration**: Album and track list views moved to `CustomScrollView` with sliver widgets, including a new `MultiDiscSliverList` for multi-disc albums.
- **Album detail header**: Removed the artwork widget from the album detail header for a simpler, more consistent layout.
- **Chrome visibility lifecycle**: `ScrollChromeListener` now reliably notifies `libraryChromeVisibleProvider` on disposal so chrome state is always cleaned up correctly.

### Core & Networking

- **`audioSearch` method**: New entry point in the MCWS API client. `McwsClient` calls it directly, dropping redundant media-type filters and improving query precision.
- **Album track sorting**: `getAlbumTracks` now appends sort parameters regardless of folder-path status, ensuring consistent ordering.
- **Queue state**: Refactored to a single `select` on `queueProvider`, with view logic extracted into dedicated widgets (`_DataView`, `_EmptyView`, `_Header`, `_UpNext`).
- **Zone helpers**: New consumer-friendly providers — `isAndroidAutoActive`, `isOfflineLikeActive`, `isVirtualZoneActive` — and a corrected `setZone` that handles transitions from any serverless state.
- **Favorites**: Switched to `ref.invalidateSelf()` to resolve a Riverpod self-dependency assert.

### Build & Dependencies

- **Dart SDK**: Bumped along with `share_plus`, `flutter_launcher_icons`, `talker`, `build`, `built_collection`, and `flutter_secure_storage`.
- **macOS**: Updated Xcode project signing (team ID, bundle identifier) and relaxed ATS restrictions in `Info.plist`.

## Migration notes for developers

- **Audio service architecture**: `JrrAudioHandler` now composites multiple player handlers. `LocalPlayerService` inherits from a shared `LocalPlayerServiceBase`; `AndroidAutoPlayerService` is the dedicated handler for the AA zone.
- **Media IDs**: AA media IDs encode parent paths via a `_join` helper so the player can reconstruct a parent queue from any child track. New browse handlers (`_downloadsChildren`, `_recentChildren`, `_artistsChildren`, `_albumsChildren`, `_artistAlbumsChildren`) accept a `parentPath` argument.
- **MCWS queries**: Prefer `McwsClient.audioSearch(...)` over hand-rolling `[Media Type]=Audio` filters; the helper handles encoding and exact-match expectations.
- **Sliver widgets**: When adding to album or track detail screens, wrap new widgets in `SliverToBoxAdapter` or implement them as slivers. Use `MultiDiscSliverList` for multi-disc track listings.
- **Zone checks**: Use the new boolean providers (`isAndroidAutoActive`, `isOfflineLikeActive`, `isVirtualZoneActive`) instead of comparing zone IDs directly.
